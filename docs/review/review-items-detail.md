A1. **[High]** A partially-built composite session leaks every backend connection it already opened — `src/ActiveSync.Core/Backend/CompositeBackendSession.cs:59` (`CompositeBackendSession.CreateAsync`). `IBackendConnection connection = await provider.CreateConnectionAsync(...); session._connections.Add(connection);` — the provider loop has no `try`/`catch`, and neither does the pair of assertions that follow it (`session.MailStore = ... ?? throw new InvalidOperationException("No provider filled the MailStore role for this session.")`, `:68`–`:71`). When provider 2 throws (bad `BaseUrl` → `new Uri(...)` in `CalDavBackendProvider`/`CardDavBackendProvider`/`JmapBackendProvider`, `Roles.Single(...)` with no matching role, `caldav cannot serve the {role} role`, or any plugin whose transport open fails), the `CompositeBackendSession` is never returned, so nothing ever calls `DisposeConnectionsAsync` on the connections already in `_connections`. The one cleanup path, `BackendSessionFactory.DisposeLazyAsync` (`BackendSessionFactory.cs:383`), does `try { session = await AwaitBuild(lazy); } catch { return; }` — it explicitly gives up on a faulted build. So every failed build leaks provider 1's owned resources (`ImapSession`, and for DAV/JMAP a `WebDavClient`/`JmapClient` holding an undisposed `SocketsHttpHandler` and its connection pool). `GetSessionAsync` retries a faulted build once (`:227`–`:239`), so one request against a half-broken configuration leaks two; a phone Pinging every 60 s leaks ~120/hour/device, silently, until sockets or the mail server's per-user connection limit run out — at which point the *healthy* IMAP backend starts refusing logins and mail sync stops with an unrelated error. AGENTS.md ("Backend layer notes") states providers open their transport in `CreateConnectionAsync`, so a contract-conforming plugin leaks a live socket, not just a managed object. FIX: wrap the whole body of `CreateAsync` after `session` is constructed in `try { … } catch { await session.DisposeConnectionsAsync(); throw; }` (make `DisposeConnectionsAsync` swallow-and-log in that path so a cleanup failure cannot mask the original exception), covering both the provider loop and the two `?? throw` assertions.
